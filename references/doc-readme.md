# Template: README

The front door. What it is, why it exists, how to use it. One page. Tier 1 and up.

## Questions it must answer

- What is this, in one sentence?
- What's the bet / the wedge - the one non-obvious thing it gets right?
- What does a user (or a consuming app) actually get?
- Who is it for?
- How do you run / install / enter it?
- What's the current status?

## Required sections

- `# <name>` + a one-line definition directly under it.
- `## The bet` (or `## The wedge`) - the non-obvious thesis in two or three sentences.
- `## What you get` - the concrete capabilities, as a list.
- `## Who it's for` - the target user or consumer.
- `## Getting started` (or `## How we enter`) - run / install steps, or the entry sequence.
- `## Status` - what's done, what's next, honestly.

## Good vs slop

Good: a stranger reads it and knows what it is, who it's for, and whether to keep reading, in thirty seconds. Slop: a feature dump with no thesis, or a thesis with no way to actually run it.
